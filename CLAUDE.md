# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

FLUXGhost is the local Python backend for Beam Studio (FLUX's laser cutting/engraving software). It exposes a websocket API on `127.0.0.1:8000` (default) that the Beam Studio frontend connects to for device discovery, machine control, camera streaming, calibration, and SVG→FCode toolpath generation. The heavy lifting is delegated to the `fluxclient` library (plus `fluxsvg`/`beamify` for SVG processing).

See [docs/architecture.md](docs/architecture.md) for the full architecture, endpoint list, and message protocol; [docs/api/](docs/api/README.md) for per-endpoint websocket API references; and [docs/todo.md](docs/todo.md) for known issues and cleanup candidates.

## Harness Rules (read before doing anything)

These docs were written and verified end-to-end on 2026-07-05 — every build step was executed, every endpoint doc was written from the handler source, and the smoke suite passed 8/8 on a real run. Trust these rules over your own inference; when they conflict with something you derived, the rules win. When they conflict with the *code*, the code wins — then fix the doc.

1. **Verify with the smoke suite, always.** After any code change, run `uv run python tools/ws_smoke.py`. It spawns the server itself (no hardware needed) and must end with `ALL PASS`. If you touched toolpath code, the `toolpath.divide_svg` line must be `PASS` — a `SKIP` there means your environment is broken, not that you're done. Do not claim success without this output.
2. **If you change an endpoint the smoke suite doesn't cover** (calibration, utils, opencv, ...), write a check for it before finishing — the `WS` class in [tools/ws_smoke.py](tools/ws_smoke.py) is a reusable stdlib-only websocket client, and `docs/api/<route>.md` gives you the exact messages to send and expect.
3. **Look up, don't guess.** Per-endpoint protocol truth is `docs/api/<route>.md`; routing truth is `fluxghost/http_websocket_route.py`. The inline docstrings in `fluxghost/websocket/*.py` contain known errors (wrong route names, Delta-era examples) — never cite them as authority.
4. **Cross-repo contract — never change unilaterally:** command strings in any `cmd_mapping`, response `status` values, response field names, the stdout line `{"type": "ready", "port": N}`, and the `FluxStudioPort` file. Beam Studio (`packages/core/src/web/helpers/api/*` in the beam-studio repo) string-matches all of these. A rename here without a synchronized frontend change is a breakage, even if all local tests pass.
5. **Python 3.8 syntax only.** Forbidden: `x | y` on dicts, `list[str]`/`dict[str, int]` annotations, `match`/`case`, `str.removeprefix/removesuffix`, walrus is OK (3.8), `functools.cache` (use `lru_cache`). Ruff is configured for py38 and will not catch everything — the runtime will.
6. **Known traps (all verified, don't rediscover them):**
   - `--simulate`/`-s` is a **dead flag**. The simulated device registers under `-d`/`--debug` (`http_server_base.py:96-100`).
   - On Apple Silicon, `lib/mac` dylibs are x86_64-only; run with `DYLD_FALLBACK_LIBRARY_PATH=/opt/homebrew/lib` (brew cairo). `tools/ws_smoke.py` sets this automatically.
   - Route regexes are prefix-matched and unanchored — adding a route whose name is a prefix/suffix of another can shadow it. Check `http_websocket_route.py` order.
   - `requirements.txt` is generated by the pre-commit hook from `uv.lock` — never edit by hand.
   - fluxclient/fluxsvg/beamify are installed from sibling checkouts, not from uv.lock (see Development Commands).
7. **Keep docs in sync — this is part of any change, not optional.** Changed endpoint behavior → update `docs/api/<route>.md` in the same change. Fixed something listed in `docs/todo.md` → check it off. Found a new issue you're not fixing → add it to `docs/todo.md`. Do not let these docs rot; they are the only protocol reference (the GitHub wiki is stale).
8. **Scope discipline.** Don't refactor Delta-era legacy or fix lint outside the lines you changed. If you notice something worth fixing, add it to `docs/todo.md` instead of expanding the diff.

## Development Commands

The project uses [uv](https://docs.astral.sh/uv/) and is **pinned to Python 3.8** (`requires-python = ">=3.8,<3.9"`, `.python-version`). uv downloads the correct interpreter automatically.

```bash
# Install dependencies (creates .venv with Python 3.8)
uv sync

# fluxclient/fluxsvg/beamify are NOT in uv.lock — install from sibling checkouts
# (fluxclient is also available as the git submodule at ./fluxclient)
uv pip install ../fluxclient-dev
uv pip install ../beamify/python     # note: the package is in beamify/python
uv pip install ../fluxsvg            # public repo: github.com/flux3dp/fluxsvg

# fluxsvg needs native cairo. On Apple Silicon the bundled dylibs in lib/mac
# are x86_64-only, so use Homebrew cairo and export the fallback path:
#   brew install cairo
#   export DYLD_FALLBACK_LIBRARY_PATH=/opt/homebrew/lib

# Run the server
uv run ghost.py                      # 127.0.0.1:8000
uv run ghost.py --port 0             # auto-assign port (what Beam Studio does)
uv run ghost.py -d                   # debug logging
uv run ghost.py -s                   # simulate a device without hardware
uv run ghost.py --allow-foreign      # accept non-localhost websocket origins

# Smoke tests (import checks for every websocket route)
uv run ghost.py --test

# Version check (prints fluxghost + fluxclient versions)
uv run ghost.py --version

# Lint / format (ruff, line-length 120, single quotes, target py38)
uv run ruff check --fix
uv run ruff format

# Install git hooks (ruff + uv-lock/export on commit)
uv run pre-commit install
```

### Packaging

- **Desktop binary**: `pyinstaller ghost.spec` → `dist/ghost/flux_api`. Beam Studio's Electron app spawns this binary (see `apps/app/src/node/backend-manager.ts` in beam-studio).
- **Docker**: `docker compose build && docker compose up -d`. The build context is the **parent directory** and expects sibling checkouts: `fluxghost`, `fluxclient-dev`, `fluxsvg`, `beamify`.
- `requirements.txt` is generated from `uv.lock` by the pre-commit hook — never edit it by hand.

## Architecture (short version)

- [ghost.py](ghost.py) — CLI entry point; starts `HttpServer` (a `select()`-based loop in [fluxghost/http_server_base.py](fluxghost/http_server_base.py)) which upgrades HTTP requests under `/ws/...` to websockets.
- [fluxghost/http_websocket_route.py](fluxghost/http_websocket_route.py) — the regex route table mapping `/ws/<path>` to handler classes. **Add new endpoints here.**
- `fluxghost/websocket/*` — thin transport wrappers, one per endpoint, subclassing `WebSocketBase`.
- `fluxghost/api/*` — the actual endpoint logic, written as **mixin factories** (`xxx_api_mixin(cls)`) applied to the websocket class. [fluxghost/api/api_base.py](fluxghost/api/api_base.py) defines the response vocabulary (`send_ok`, `send_json`, `send_error`, `send_fatal`, `send_progress`, `send_binary_buffer`, ...).
- `fluxghost/simulate/` — fake device/robot/camera used by `--simulate`.
- `fluxghost/utils/` — websocket frame codec, camera calibration (charuco/fisheye), contour utilities.

## Critical Constraints

1. **Don't break the stdout ready line.** On startup the server prints `{"type": "ready", "port": <port>}` to stdout ([http_server_base.py:84](fluxghost/http_server_base.py)). Beam Studio's `backend-manager.ts` parses exactly this line to learn the auto-assigned port. Anything else printed to stdout before it must remain valid-JSON-free.
2. **Frontend/backend command names must stay in sync.** Handler `cmd_mapping` keys (e.g. `svgeditor_upload`, `go`, `g2f` in [fluxghost/api/svgeditor_toolpath.py](fluxghost/api/svgeditor_toolpath.py)) are string-matched by Beam Studio's clients in `packages/core/src/web/helpers/api/`. Renaming a command is a cross-repo breaking change.
3. **Response `status` values are a protocol.** The frontend switches on `status`: `ok`, `error`, `fatal`, `connecting`, `connected`, `continue`, `progress`, `computing`, `complete`, `pong`, `binary`. Use the `ApiBase.send_*` helpers instead of hand-rolled JSON.
4. **Python 3.8 only.** No walrus-free zone concerns, but no 3.9+ syntax (`dict | dict`, `list[str]` annotations at runtime, etc.). Ruff targets py38.
5. **Security default is localhost-only.** Non-local connections are rejected unless `--allow-foreign` is passed; keep new endpoints safe under that assumption (they trust their caller).

## Testing Notes

- **Quick pre-flight**: `uv run python tools/ws_smoke.py` — spawns the server with the simulated device and runs 8 protocol checks. Must end `ALL PASS`.
- **Regression suite**: `uv run python -m unittest discover -s tests/usage -t . -v` — 39 usage-based protocol tests derived from real Beam Studio call patterns (plan and case list in [docs/test-plan.md](docs/test-plan.md); shared fixtures in `tests/usage/_harness.py`). Run this after any endpoint change; run the relevant module alone for faster iteration (e.g. `-m unittest tests.usage.test_control -v`). Some tests deliberately pin known quirks — fixing a quirk means updating the test in the same change.
- `uv run ghost.py --test` only verifies imports ([tests/main.py](tests/main.py)); it is necessary but not sufficient.
- `-d` (not `--simulate`) registers the simulated device: uuid `00000000000000000000000000000000`, auth accepted for any key, `file ls SD` serves a fake filesystem, camera streams PNG at 4 fps.
- The `toolpath` route import fails without `fluxsvg`/`beamify` installed; that is expected in a minimal checkout but NOT acceptable when working on toolpath code.
